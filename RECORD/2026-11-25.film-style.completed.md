# Film style (v2)

## 2026-11-25 — goal and plan

- Request: a v2 of the rain that looks more like the monitors in *The Matrix*
  (1999), with depth.
- What the film look needs, compared with v1: green only (no rainbow); mirrored
  half-width katakana plus digits and a few symbols; narrow columns (glyphs taller
  than wide); bright, almost white heads with a glow; long trails fading to dark
  green; several drops per column.
- Depth: several layers of columns. Farther layers have smaller glyphs, are
  dimmer, denser and slightly blurred, and fall slower on screen (same rows per
  second over smaller rows, which is the right parallax).
- Decision: keep v1 as `--style rainbow`; v2 is `--style film` and becomes the
  default (version 0.2.0).
- Decision: layers overlap, so the cell-based partial redraw of v1 does not fit.
  The film style adds glyphs (with a pre-computed glow) into a 16-bit light
  buffer in ordinary RAM (4 MB at 1920×1080). A palette then maps light to colour
  (green, burning to white above full brightness) in one sequential pass into the
  scan-out buffer. That costs more CPU than v1; to be measured with `--bench`.

## 2026-11-25 — implementation

- Code split into modules: `src/rainbow.rs` (v1, moved unchanged apart from
  taking the font as a parameter), `src/film.rs` (v2), `src/main.rs` (options,
  display, bench, capture, and a `Scene` enum over the two styles). New options
  `--style film|rainbow` (default `film`) and `--layers N` (default 4).
- Look: mirrored half-width katakana (U+FF66–U+FF9D, 85 % of glyphs), digits and a
  few symbols; columns 0.62 × the glyph size; 2 drops per column; trail length and
  speed in rows are the same at every depth (correct parallax); heads always at
  2.2 × full light, so they burn white; glow (two box blurs) only on glyphs at
  ≥ 55 % light; the farthest layers are blurred by 1 px; layers from 100 % down to
  40 % of `--size`, brightness 100 % → 25 %.
- Performance, in order (`--bench`, ms per frame at full clock, 1920×1080):
  - first version, 16-bit light buffer, glow on every glyph: 12.0 ms.
  - 8-bit light buffer, trail length constant in rows: 7.4 ms.
  - glow only on bright glyphs, dark runs of 8 px skip the palette: 6.4 ms.
  - skipping the empty parts of glyph rows: 6.2 ms (pixel count was not the
    bottleneck).
  - building the frame in 64-row bands (light buffer of one band, 120 KB, stays in
    cache): 4.4 ms. The cost had been cache misses: every glyph row touched a
    different line of a 2 MB buffer, layer after layer.
  - sparser layers, final look: ~4.0–4.2 ms (~8.5k glyphs per frame); paced at
    30 FPS, ~25 % CPU time (low clock). `--layers 2`: 2.5 ms; `--layers 3`: 3.4 ms.
  - `-C target-cpu=native` made no difference, so it is not used.
- The rainbow style is unchanged: 0.9 ms per frame, same output.
- Note: `cargo fmt` is not used in this repository (lines are longer than its
  default width); `src/film.rs` was formatted with
  `max_width=130, use_small_heuristics=Max`, which is close to the existing style.
- Not done yet: running the film style as the kiosk service on the display and
  measuring RSS and CPU there (the service on the target machine still runs the
  installed v1 binary).

## 2026-11-25 — feedback: blurry, keep v1 colours, different speeds

- Feedback after the first version: it looked somewhat blurry; the v1 colours
  should be kept; drops should fall at clearly different speeds.
- Sharper: removed the 1 px out-of-focus blur of the far layers; glow only on
  heads (it was on everything ≥ 55 % light), with a smaller radius (size/14) and
  strength (0.9); glyphs placed at whole pixels; the farthest layer is now 50 %
  of `--size` instead of 40 % (at 12 px the glyphs turned to mush).
- Colours: new `--colors rainbow|green`, default `rainbow`, with v1's formula:
  hue = ms/15 + 10° per `--size` pixels of x, hsl(hue, 80 %, 65 %) trails and
  (220, 255, 255) heads. Implemented as 120 palettes (3° steps, 120 KB) and a
  palette offset per pixel column, computed once per frame; all layers share the
  hue at a given x. Trails now fade linearly, as in v1 (the earlier curves made
  the rainbow look dull).
- Speeds: 5–24 rows/s per drop (was 9–22), a slightly wider range than v1's 6–24.
- `--bench`: ~3.5–3.7 ms per frame (fewer glowing glyphs offset the palette per
  column); paced at 30 FPS, ~28 % CPU time.

## 2026-11-25 — colours per column: `--colors full`

- Feedback: the rainbow came out as vertical bands (hue by x position); colours
  should be random per column instead. Then: keep the bands as
  `--colors rainbow` and name the new one `--colors full` (now the default).
- Since layers overlap, a per-column colour needs a colour per glyph, so the 8-bit
  light buffer and the palettes were replaced with a B, G, R, X band buffer (the
  scan-out byte order): each glyph is added in its colour, per channel,
  saturating, and the band is copied straight to the scan-out buffer. Each column
  has a starting hue (random for `full`, from its x for `rainbow`) that drifts by
  ms/15 degrees, as in v1. Heads use v1's (220, 255, 255), scaled down only by
  depth.
- Cost: ~4.4–4.8 ms per frame (`--bench`), paced ~30 % CPU time; the band buffer
  is now 490 KB at 1920 px. The palette pass is gone, but each glyph pixel now
  updates three channels.

## 2026-11-25 — no aligned columns, less saturation with depth

- Feedback: columns looked tabulated, and dark stripes appeared where the gaps
  between columns lined up; saturation should drop with depth.
- Each column now sits at its grid position plus a random offset of up to ±40 %
  of the column width (it is stored per column; the per-layer offset is gone).
  For `--colors rainbow` the hue comes from the column's actual centre.
- Saturation per layer: 100 % (near) → 30 % (far), mixing the colour towards grey
  of the same luminance, for both trails and heads.
- Depth levels are still 4 by default (`--layers`): 30, 24, 19 and 15 px glyphs
  at `--size 30`.
- `--bench`: ~4.4 ms per frame, unchanged.

## 2026-11-25 — rows not aligned; size and density options

- Feedback: the gaps must not coincide between columns. Within a layer all
  columns shared the row grid, so the gaps between rows formed horizontal lines.
  Each column is now moved up by a random 0..cell-height pixels (one extra row
  covers the bottom).
- New options: `--max-size` (synonym of `--size`), `--min-size` (default half of
  the max size; layer sizes shrink geometrically between them) and `--density`
  1–5 (default 3; each level multiplies the waits between drops by 1.6).
  `--layers` already set the number of depth levels.
- `--bench` (ms per frame): default 4.7; `--layers 3` 3.7; `--max-size 40` 4.5;
  `--density 2` 3.8; `--layers 3 --max-size 40 --density 2` 3.1.
- New `--speed-spread` (default 2.2, 1–10): drop speeds are 11 rows/s × spread^u,
  u uniform in [-1, 1] (log-uniform), so the default keeps the 5–24 rows/s range
  and larger values widen it both ways (3.5 → ~3–38 rows/s).
- Service set to `rain-kms --layers 3 --max-size 40 --density 1 --speed-spread 4`
  (film style, full colours, 1920×1080 and 30 FPS by default).
- New `--colors monokai`: each column takes one of Monokai's accent colours
  (#F92672, #FD971F, #E6DB74, #A6E22E, #66D9EF, #AE81FF) at random, without
  drifting; heads use Monokai's foreground #F8F8F2. Background stays black unless
  `--background 272822` (Monokai's) is given. Same cost as `full`.
- Service now also uses `--colors monokai` (black background).

## 2026-11-25 — installed and measured on the display

- Installed with `install.sh` on the target machine (run by the user; sudo needs
  a password). The running binary and unit match the repository; the service
  runs `--layers 3 --max-size 40 --density 1 --speed-spread 4 --colors monokai`
  at nice 10, 1920×1080 @ 60 Hz, 30 FPS. No restarts.
- RSS 4.6 MB (1.6 MB anonymous, 3.0 MB file-backed); peak 23 MB at start-up
  while the font is loaded; cgroup memory 1.9 MB current, 3.0 MB peak.
- CPU, measured from /proc over two 30 s windows: 25.4 % and 26.4 % of one core
  (`powersave` governor). That is about twice the rainbow style (~12.5 %) and
  more than the paced `--bench` figure (~19.5 %), as on the display each frame
  also waits for the page flip and the CPU stays at a low clock.
- If it competes with other services: fewer layers, lower density, or
  `--style rainbow`.
