# Service priority

Follow-up to `2026-11-25.initial-implementation.completed.md`.

## 2026-11-25

- `rain-kms.service` was running at normal priority (nice 0, SCHED_OTHER,
  default CPU/IO weights), the same as the other services on the target machine.
  Under load (e.g. a media server transcoding 4K) it would compete with them
  on equal terms.
- Decision: the rain is decorative, so it should give way. Added `Nice=10`,
  `CPUWeight=20` and `IOSchedulingClass=idle` to the unit. It may drop a few
  frames while the machine is busy.
- On the target machine, the services that should win (a media server and
  another local service) were raised with systemd drop-ins outside this
  repository (`Nice=-5`, `CPUWeight=200`, `IOWeight=200`).
- Verified after reinstalling: nice 10 on the process, `cpu.weight` 20 in its
  cgroup, I/O class idle; the installed unit matches the repository.
- Note: CPU/IO weights only compare units within the same slice; user services
  (in `user.slice`) are only affected through nice.

## 2026-11-25 — summary

Done: the kiosk service now runs at low priority; README documents it.
