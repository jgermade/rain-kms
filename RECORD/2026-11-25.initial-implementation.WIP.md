# Initial implementation

## 2026-11-25

### Goal

Show a kiosk screen with content like the canvas demo in
`wasm-gaming/engine-specs/demo/canvas-renderer.js` (katakana rain with rainbow
hues), using as little RAM as possible.

### Decisions

- **Native Rust drawing straight to DRM/KMS** instead of a browser kiosk
  (Firefox + cage, estimated 300–500 MB) or a Wayland client inside cage.
  No compositor or display server is involved.
- **Own implementation, not a copy** of the demo: the source repository has no
  licence, so the effect was rewritten from scratch.
- **Default mode 1920×1080** even though the target display is 4K: a 4K scan-out
  buffer is 33 MB (66 MB double-buffered) and software rendering at 4K costs far
  more CPU on the target machine (Alder Lake-N, 4 cores). The display upscales.
- **Glyph cache**: the 96 katakana (U+30A0–U+30FF) are rasterised once with
  `ab_glyph` (lazy parsing, unlike `fontdue`, which preloads every glyph of the
  CJK font); the ~20 MB font file is dropped right after.
- **No read-back from video memory**: glyphs are blended against the known
  background colour, which avoids slow reads from write-combined buffers.
- **Double buffering with page flips** synced to vblank, plus a frame-rate cap
  (default 30 FPS) to save CPU.
- **`--card auto`**: the DRM card index can change between boots.
- **`--capture`**: renders a frame to a PPM file to check the output without a
  display (used during development over SSH).
- The FPS overlay of the original demo was left out: it is a benchmarking aid
  and not useful on a kiosk.

### Measurements (target machine, 1920×1080 @ 60 Hz, 30 FPS)

- Binary: ~450 KB (release, LTO, stripped).
- RSS: ~2.6 MB steady; 22 MB peak during start-up (font load).
- Scan-out buffers: 2 × 8 MB, allocated by the driver.
- CPU: ~17 % of one core.

### Status

- Builds cleanly (`cargo build --release`, `cargo clippy`).
- Tested on the real display over HDMI and with `--capture`.
- `install.sh` and `rain-kms.service` written; **not yet installed** on the
  target machine.

### Open questions

- Hardware-accelerated rendering is not needed at current CPU usage; revisit if
  4K output is required.
- Graceful handling of SIGTERM (currently the kernel releases the display when
  the process exits).
